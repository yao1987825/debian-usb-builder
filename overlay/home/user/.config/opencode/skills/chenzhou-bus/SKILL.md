# 郴州实时公交

这台机器上装了 `bus` 命令, 查郴州的公交**线路、站点、实时车辆、发车时刻表**
都能查 —— 数据来自「郴州公交行」安卓客户端的接口。

> ⚠ 这个接口是**非公开接口**, 随时可能变更或失效。查不到东西时先看下面的
> "会遇到的情况", 别急着下结论说"没有这路车"。

## 怎么用

所有子命令都支持 `--json` 出结构化输出 —— **优先用 `--json`**, 字段稳定,
比解析中文表格可靠得多。

### 搜线路 / 站点 / 地标

```bash
bus search 2路
bus search 火车站 --json
bus search 火车站广场
```

`--json` 返回 `{"keyword", "lines":[], "stations":[], "places":[]}`。
`lines[].id` 就是**线路ID**, 后面查站点/实时车辆都要用。

### 查某条线路的站点表

```bash
bus line 20000002            # 去程
bus line 20000002 1          # 返程
bus line 20000002 --json
```

站点从 1 开始编号, `stations[].num` 就是站序 —— **实时车辆查询用的就是这个序号**。

### 查实时车辆(某站还有几辆车要来)

```bash
bus realtime 20000002 5       # 2路 第5站
bus realtime 20000002 5 --json
```

返回 `vehicles[]`, 每条含:

| 字段 | 含义 |
| --- | --- |
| `plate_num` | 车牌号(湘L开头) |
| `next_station_name` | 下一站 |
| `station_distance` | 距本站还有多少米 |
| `station_arriving_text` | 预计多久到(人话, 比如"1分钟") |
| `arrived` | 是否已停靠本站 |
| `congestion` | 拥堵等级: 畅通 / 缓行 / 拥堵 |

### 发车时刻表

```bash
bus schedule 20000002
bus schedule 20000002 --json
```

分平峰/高峰, 给出首末班时间和全部发车时刻。

### 附近站点

```bash
bus nearby 25.7936 113.0176 800
bus nearby 25.7936 113.0176 800 --json
```

⚠ **经纬度必须是 GCJ-02(火星坐标)** —— 和高德/腾讯地图一致。
如果用户给的是 GPS 原始坐标, 得先转:

```python
from chenzhou_bus.coords import wgs84_to_gcj02
lat, lon = wgs84_to_gcj02(raw_lat, raw_lon)
```

### 交互式

```bash
bus cli
```

进去以后是 `bus>` 提示符, 可用命令跟上面一样(多一个 `help`)。

## 会遇到的情况

| 现象 | 原因 / 怎么办 |
| --- | --- |
| 一直连不上 / 超时 | 先 `bus search 2路` 试一下通不通; 都不通就是接口挂了或网络不通 |
| 查线路返回空 | 关键词要带"路"(比如"2路"而不是"2"); 站名要全称 |
| 实时车辆是空的 | **很正常** —— 深夜、或者那个站此刻确实没有车在跑。这时该说"当前没有车辆接近该站", 而不是"公交坏了" |
| 实时车辆只有一两辆 | 正常, 这就是实况 |
| 想查全量线路 | `bus lines` 只显示前 50 条, `bus lines all` 显示全部 |

## 汇报给用户时

- **实时信息要给清楚三个要素**: 哪一路车、还有几分钟/多少米到、下一站是哪儿;
- 距离远(几百米以上)或预计超过 5 分钟时, 提醒用户**可以再等一会儿**;
- 同一线路有去程/返程两个方向, 方向不同站点顺序完全不同 —— 跟用户确认一下;
- 如果实时车辆为空, 明确说"当前没有车接近该站", 并可以补一句末班时间
  (用 `bus schedule` 查), 别让用户以为查询失败。
